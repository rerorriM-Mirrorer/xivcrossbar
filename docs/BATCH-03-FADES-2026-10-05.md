# Batch 3 — Fade transitions

Build `0.4.0-a.20261005.11`.

Requested: “Fade in and fade out on hide/display as well as load/before unload
-- would make entire thing feel so much more coherent and smooth and responsive
and might help with graphical hitch when drawing.”

Crossbar and binding-menu panels fade in over 120 ms and out over 180 ms.
Images, text, strokes, backgrounds and native primitives share the panel's
opacity while retaining their own configured alpha. Fades use elapsed time,
run before frame skipping, reverse from their current opacity and do not delay
input. A closing menu retains only its still-visible rows through the fade,
then releases them. The initial load gets a brief visual preview.

Use `//xb unload` or `//xb restart` for fade-before-unload/reload. They schedule
the ordinary Windower command after the closing transition. Direct
`//lua u xivcrossbar`, `//lua r xivcrossbar`, a crash or closing the game can
tear down the Lua instance immediately; those paths get cleanup, not a promised
pre-unload animation. `//xb reload` still reloads hotbar data as before.

Settings: `Animation.Enabled`, `Animation.FadeIn`, `Animation.FadeOut`.
Durations are seconds, clamped to 0–1; zero makes that transition immediate.

Validation covers timed opacity, rapid reversal, original alpha preservation,
native primitive visibility, post-fade resource release and no load flash.
Native smoothness and any drawing hitch require an in-game comparison. Fading
does not remove the initial work of loading a new texture.
